# Workshop Starter v0.2.8

> Проверено 14.10.2026: Windows — Claude Code и Codex; macOS — Claude Code (установка, страница, commit, push на GitHub); Vercel — живой деплой и закрытые служебные файлы; отладка по фактам — Claude Code (живой разбор ошибки) и Codex (выбор skill) на Windows. Codex на macOS не проверялся.

Базовая настройка проекта для Codex и Claude Code на Windows и macOS. Один пакет — одинаковый порядок работы в обеих средах: сначала договориться, потом код; проверять результат, а не верить «готово»; записывать состояние, чтобы продолжить в новом чате. Задачу, стек и критерии результата определяет пользователь. Приложение при установке не создаётся.

## Пример

Вы распаковали Starter, открыли папку в агенте и написали: «Хочу страницу-калькулятор для идеи кафе». Агент уточнит важное, предложит первую версию и критерии готовности, запишет их в `docs/PRODUCT.md`, после вашего «да» сделает страницу в `public/`, проверит её на ширине ноутбука и телефона, сохранит локальный commit и запишет состояние в `docs/HANDOFF.md`. Публикация — только по отдельному «да».

## Начать новый проект

1. Распакуйте ZIP. Найдите папку, **непосредственно содержащую `AGENTS.md`**, — Windows может добавить лишний внешний уровень.
2. Переименуйте её в имя своего проекта и перенесите в обычную папку для проектов, например `Projects` в домашнем каталоге. На macOS не работайте в «Рабочем столе» и «Загрузках».
3. Проверьте, что на месте папки `.agents`, `.claude`, `.codex` и файл `.gitattributes`. Windows обычно показывает их сразу; если не видите — включите показ скрытых элементов. macOS: Command + Shift + . (точка).
4. Откройте эту папку в агенте как локальный проект и включите режим:
   - **Claude Code** — в переключателе у поля ввода выберите **Auto**;
   - **Codex** — подтвердите доверие к папке при первом открытии и выберите **Approve for me**. Если пункта нет, спросите агента, какие режимы доступны; sandbox не отключайте.
5. Отправьте:

```text
Сначала проверь, что AGENTS.md лежит прямо в этой папке; если нет — назови, какую папку открыть, и остановись.
Подготовь Workshop Starter в текущей папке к работе по INSTALL.md.
Прочитай правила, примени workshop-copilot и проверь установку.
Глобальные настройки не меняй. Помоги согласовать первую версию проекта.
```

Каждый новый проект — свежая распаковка Starter в новую папку. Для существующего проекта не распаковывайте архив поверх: используйте сценарий Б из [INSTALL.md](INSTALL.md).

## Возможности

- Согласование задачи и критериев готовности до кода; контрольный пример в `docs/PRODUCT.md`.
- Проверка результата с фактическим выводом команд: страницы — у себя в браузере на ширине ноутбука и телефона, серверные функции — на Vercel.
- Сайт публикуется из `public/` через `vercel.json`: правила и документы проекта по ссылке не открываются — агент проверяет это после деплоя. Без `vercel.json` Vercel публикует весь корень проекта — проверено живым деплоем.
- Локальные Git checkpoints; публикация только после вашего «да» (можно дать сразу в запросе) и ревью одним независимым reviewer.
- Отладка по фактам: агент воспроизводит ошибку, ищет причину, проверяет тем же сценарием и после двух неудачных попыток останавливается с отчётом, а не угадывает дальше.
- Мелкие правки — сразу, без плана и документов.
- Продолжение работы: «Продолжаем проект. Где остановились и какой следующий шаг?» — в той же сессии; перед новым чатом — «Подготовь handoff».
- Пошагово или автономно через `/goal`, если команда доступна.

## Что сказать агенту

Обычными словами — агент сам выберет нужный порядок работы.

| Ситуация | Что написать |
|---|---|
| Новая задача | «Хочу [что]. Уточни важное и предложи первую версию» |
| Мелкая правка | «Поменяй [что] на [что]» |
| Что-то не работает | «Не работает: [что делал и что увидел]» |
| Вернуться к проекту | «Продолжаем проект» |
| Перед новым чатом | «Подготовь handoff» |
| Публикация | «Выложи проект: код — в приватный репозиторий на GitHub, сайт — на Vercel. Это моё «да»» |
| Свежие сведения | «Проверь по официальной документации, как сейчас работает [сервис]» |
| Задача целиком, без пошагового согласования | `/goal` + цель и способ проверки (если команда есть в вашей версии) |

## Как это работает

Правила и workflow — текст: агент читает `AGENTS.md` (Claude Code — через `CLAUDE.md`) и skill. Разрешения применяет само приложение по файлам настроек; промпт их не заменяет. Личные и корпоративные настройки действуют вместе со Starter и могут быть строже.

| | Claude Code | Codex |
|---|---|---|
| Режим работы | Auto — выбирается в приложении | Approve for me — действия вне песочницы одобряет автоматический reviewer |
| Настройки проекта | Применяются сразу | Только для доверенной папки |
| Подтверждение перед `git push` | Окно подтверждения для вас | Команды вида `git push …` проверяет автоматический reviewer — он видит ваше «да» в переписке; сохранённое «всегда разрешать» их не пропускает |
| Чтение `.env` | Запрещено настройкой проекта | Настройкой не запрещено; агент не читает его по правилам |

## Ограничения

- `.gitignore` не запрещает чтение; запрет чтения в Claude Code не изолирует произвольные команды оболочки. Перед commit, ZIP или публикацией проверяйте состав файлов.
- Если ваши личные запреты строже, агент может не прочитать даже `.env.example` — это нормально.
- В Codex запреты `.codex/rules` и проектный `config.toml` работают только в доверенной папке.
- Проверено на Windows: Claude Code 2.1.296, CLI (секреты, push, force-push, reset, skill); Codex app (skill, AGENTS.md, сеть и git через auto-review, запрет force-push, проверка push). macOS: Claude Code — установка, проверка страницы, commit и push после входа через `gh`. Не проверено: Codex на macOS.
- Коннектор Vercel может не создать новый проект (ошибка 403). Тогда импортируйте репозиторий на vercel.com (Add New → Project → Import) или выложите через Vercel CLI.
- Запрещены типичные формы опасных команд, а не все варианты. Claude Code: `git push origin main --force` и `--force-with-lease` попадут под подтверждение, а не под запрет.
- Codex: правила ловят начало команды: `git push origin main --force` попадёт только на проверку, а не под запрет; `git -C папка push` правило не видит вовсе.
- Автоматический reviewer Codex может ошибаться; он не заменяет ваше «да» на публикацию.
- Для `git push` нужен отдельный вход в GitHub в Git — коннектор GitHub у агента его не заменяет. Если Git просит логин: `gh auth login --web --git-protocol https`, затем `gh auth setup-git` в своём терминале.

## Как развивать настройки

Starter — стартовая точка. Правила растут из реальных ошибок, а не заранее:

1. **Ошибка повторилась** — попросите агента предложить одну строку правила: в `AGENTS.md` этого проекта или в личные настройки для всех проектов.
2. **Правило есть, а ошибка повторяется** — нужен механизм, а не ещё одна строка: запрет или подтверждение в `.claude/settings.json` или `.codex/rules/`.
3. **Одна и та же процедура из нескольких шагов** — оформите её в skill.

После каждого завершённого этапа агент сам добавляет к отчёту блок **«Можно улучшить»** — до трёх подсказок по фактам этой работы: правило, skill, hook или идея по продукту. Нечего предложить — блока нет. Принятые идеи попадают в `PLANS.md` → Later.

Раз в несколько проектов отправьте агенту:

```text
Проведи аудит настроек этого проекта и моих личных настроек.
Ничего не меняй. Найди: какие ошибки повторялись в PLANS.md, HANDOFF.md
и истории commit; какие правила не сработали; какие процедуры
я повторяю вручную. Предложи не больше трёх правок — для каждой:
слой (проект или личные), конкретный текст и какую проблему она решает.
```
